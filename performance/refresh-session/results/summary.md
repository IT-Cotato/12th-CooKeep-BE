# A/B 측정 요약

## 대상과 조건

- A: `b68c85c`, DB `user_sessions`
- B: `363fa0a`, Redis Session + Rotation + 재사용 탐지
- 50 VU, 180초, closed workload
- 180초 워밍업 별도 실행
- seed 100명: 워밍업 10명, 본 측정 50명, 예비 40명
- A/B 각각 유효 결과 5회
- 교차 순서: A1→B1, B2→A2, A3→B3, B4→A4, A5→B5
- 대표값: 중앙값

## 결과

| 지표 | A 중앙값 | B 중앙값 | 변화 |
| --- | ---: | ---: | ---: |
| RPS | 257.22 | 292.45 | **13.7% 증가** |
| 평균 | 193.99ms | 170.60ms | **12.1% 감소** |
| p95 | 336.62ms | 301.99ms | **10.3% 감소** |
| p99 | 584.42ms | 431.97ms | 26.1% 감소 |
| 오류율 | 0% | 0% | 동일 |

구현별 중앙값 비교는 A 5회의 중앙값과 B 5회의 중앙값을 비교한 값이다. 이 기준에서 B는 A 대비 RPS가 13.7% 증가하고 평균 응답시간과 p95가 각각 12.1%, 10.3% 감소했다.

시간대가 가까운 A/B를 같은 라운드에서 비교한 변화율 중앙값은 RPS 10.6% 증가, 평균 응답시간 9.7% 감소, p95 9.8% 감소였다. p95는 5개 라운드에서 모두 감소했지만 A/B 회차별 범위가 일부 겹쳐 개선 폭에는 실행 환경 변동이 포함됐을 수 있다. p99 중앙값은 감소했지만 라운드 2·4에서는 악화됐고 B 최대값이 A보다 커, 꼬리 지연이 안정적으로 개선됐다고 단정하지 않았다.

## 저장소 부하

- `user_sessions` SELECT: A 요청당 약 0.998회 → B 0회
- 전체 MySQL statement: A 요청당 5.958~5.970회 → B 4.946~4.957회
- Redis Lua: B 요청당 `EVALSHA` 1회, 내부 `GET`·`SET` 각 1회
- Lua 호출당 실행시간 중앙값: 약 51.81μs
- MySQL `Max_used_connections`: A/B 모두 11

## 해석

B는 새 Refresh JWT와 Cookie 생성, SHA-256 digest, Lua Rotation 비용을 포함하고도 로컬 측정에서 처리량과 평균·p95 지연이 개선됐다. 핵심 구조 변화는 Refresh Session 확인을 위한 DB SELECT를 제거하고 TTL·원자적 Rotation·재사용 탐지를 Redis로 옮긴 것이다.

후반 라운드에서 특히 A의 처리량 저하와 응답시간 증가가 관측됐다. 장시간 실행에 따른 호스트 상태, MySQL 부하 또는 기타 환경 요인이 영향을 줬을 가능성이 있으나 CPU·메모리 샘플이 실행당 경계값 2개만 수집되는 등 자원 지표가 충분하지 않아 원인을 특정할 수 없다. 따라서 이 결과는 현재 고정된 로컬 Docker 조건의 관측값이며 운영 성능을 보장하지 않는다.

## 운영 조건

동일 Refresh Token으로 동시 요청이 발생하면 재사용 공격과 정상 경쟁 요청을 구분하지 않고 활성 Session 전체를 폐기한다. 클라이언트는 Refresh 요청을 single-flight 방식으로 합쳐야 하며, 해당 제어가 없으면 정상적인 동시 요청에서도 재로그인이 필요할 수 있다. 프런트엔드 구현 여부는 이번 백엔드 측정 범위에서 확인하지 않았다.

## 요약

> DB `user_sessions` 기반 Refresh 인증을 Redis TTL 구조로 전환하고, Lua Script 기반 Refresh Token Rotation과 재사용 탐지를 적용했다. 로그인과 워밍업을 본 측정에서 분리한 뒤 50 VU·180초 조건에서 A/B를 교차 순서로 각각 5회 측정했다. 구현별 중앙값 기준으로 Redis 기반 구현은 DB 기반 구현 대비 RPS가 13.7% 증가하고 평균 응답시간과 p95가 각각 12.1%, 10.3% 감소했다. 시간대가 가까운 A/B의 라운드별 변화율 중앙값은 RPS 10.6% 증가, 평균 응답시간 9.7% 감소, p95 9.8% 감소였다. 또한 요청당 약 1회 발생하던 `user_sessions` SELECT를 제거한 대신 Redis Lua 호출이 요청당 1회 추가됐다. p99는 회차별 방향과 변동 폭이 일관되지 않아 꼬리 지연이 안정적으로 개선됐다고 단정하지 않았다.
